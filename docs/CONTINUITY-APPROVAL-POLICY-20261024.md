## Policy and trusted premises

`SIA_Continuity.Approvals.Restore` first preserves every refusal/reconciliation
result from the existing checkpoint classifier. Otherwise it scans the existing
fixed claim domain, requires canonical empty observations and expected selections
at inactive slots, and returns the first unsuccessful correspondence. A later
same-slot claim supersedes earlier claims without deleting their retained history.
A revoked later selection cannot fall back to the earlier approval.

An active permission reference must match its checkpoint claim, original question
and response, independent source order, exact question event and question item,
proposal/action/conditions, and a separately selected request for this lifecycle
and turn. The independent request includes descriptor/question/item/response and
complete action scope. Selection custody targets that descriptor. Unknown,
denied, deferred, ambiguous, revoked, superseded and expired states are distinct
refusals. Direct instructions are explicitly outside this queried-decision form.
Duplicate active response identities refuse conservatively.

The postcondition establishes parent-result precedence, whole-domain successful
correspondence, or the exact first failed slot and reason. There is no precondition
that assumes the desired correspondence. A successful result is only
`References_Proposed` / `Reference_Correspondence`; no grant exists in the result.
No-permission correspondence does not establish capture completeness.

The following remain **ASSUMED INPUT PREMISES / UNPROVEN INTEGRATION**, not facts
established by the enum values or witnesses supplied to this pure package:

- A protected producer authenticates original bytes, identities, human authorship,
  transport classification and original ordering. A caller Boolean, role label,
  unkeyed digest or the model's interpretation cannot establish those properties.
- The independently selected request comes from the protected current pending
  request, not from the candidate observation. Its canonical descriptor binds all
  selected fields, including state, form, checkpoint, retention and occurrence.
  This package compares the supplied descriptor and fields; it does not hash,
  decode, authenticate or reconstruct their relationship.
- Authentication/currentness/custody evidence is fresh and complete through the
  actual restore/use boundary; the finite tuple does not prevent a later race.
- Semantic classification of an original human response is separately justified.
  A summary cannot manufacture the `Approved` enum or revive an old decision.
- The actual adapter enforces byte, input and context budgets; the protected
  actuator checks authority and reconciles uncertain operations before effects.
  The package makes no filesystem, cryptographic, Linux isolation or WCET proof.

Do not wire this package to a permissive Python producer or treat it as a new
positive action path. The existing worker refusal stays in place until the full
producer/refinement, native admission, original-record restoration and actuator
qualification is complete.

## Counterexample retained

The first candidate passed strict compilation, its initial runtime suite and all
106 scoped GNATprove checks. Independent review found that its expected input
contained only lifecycle/turn. A coherent substitution of question identity,
question item and action across the supplied observation was therefore accepted.
An additional executable refusal oracle failed with `ASSERTIONS.ASSERTION_ERROR`.
This is a **FAILED SPECIFICATION**, despite the passing proof; it is not a
witnessed bypass of an authenticated producer or installed actuator.

The revised policy binds those fields to an independent per-slot expected request
and binds custody to its descriptor. Original controls are preserved; additional
controls cover coherent whole-request, item-only and condition-only substitution,
missing/extra selections, lifecycle/turn mismatch and wrong custody target. Runtime
support is explicitly outside SPARK proof. The earlier failed source, failing
oracle, passing-but-inadequate proof, and every build/setup failure remain retained.
